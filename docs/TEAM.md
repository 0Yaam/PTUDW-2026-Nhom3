## Workflow

1. Finish the current assigned Issue before starting its dependent Cycle 3 Issue.
2. Pull the latest `main` and create a feature branch named after the new Issue.
3. Push only the feature branch and open a Pull Request linked with `Closes #<issue>`.
4. Dan (`0Yaam`) reviews member Pull Requests; Han reviews Dan's Pull Requests.
5. Only Dan can merge or update `main`.
6. Move Project status from `Ready` to `In Progress`, then `Review`, then `Done` after merge.

Do not rename or reuse old Issues for later cycles. New work always receives a new Issue.
